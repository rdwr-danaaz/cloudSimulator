# SOC-X Recommendation Simulator

**A drop-in mock of the SOC-X cloud `_getRecommendation` API**

Point any Cyber Controller (ADE) at it in minutes — no real cloud required.

<small>FastAPI · Docker · HTTPS · Web UI</small>

---

## The problem it solves

Testing and demoing the **anomaly-detection-engine (ADE)** normally requires the
live SOC-X cloud that serves protection recommendations. That is slow to set up,
hard to control, and impossible to run offline.

**This project replaces that cloud with a local simulator that you fully control.**

- ✅ Returns **deterministic, pinned** rule sets for specific networks
- ✅ **Generates** rules for any other network on demand
- ✅ Lets you **edit the recommendation JSON** from a web UI
- ✅ **Auto-wires ADE** to it over SSH (config + TLS trust + restart)
- ✅ **Many Cyber Controllers** can share one simulator at the same time
- ✅ Runs **anywhere** in one command (Docker), over **HTTPS**

## Architecture

```
                 ┌────────────────────────────────────────────┐
   Cyber         │  Simulator host (Docker)                    │
 Controller ─────┤                                             │
   (ADE)   HTTPS │  main.py  (ASGI, mounts app at / and        │
  _getRecommend. │           /socx_sim)                        │
       │         │      │                                      │
       │         │  cloud_mock_server.py  (FastAPI)            │
       │         │   ├── /api/.../_getRecommendation           │
       │         │   ├── /ui  (+ /ui/* JSON APIs)              │
       │         │   ├── permanent_responses.py  (pinned)      │
       │         │   └── response_template.py     (editable)   │
       │         │                                             │
       │  SSH    │  cc_manager.py  → configures ADE remotely   │
       └────────►│                                             │
                 │  Volume  socx-sim-data → /app/data          │
                 │     ├── configured_ccs.json                 │
                 │     └── response_template.json              │
                 └────────────────────────────────────────────┘
```

**Per-request destination matching:** the response’s `destinationIPs` is always
overwritten with the network from the incoming request, so one global template
serves many CCs correctly and simultaneously. State is **file-based** (no DB).

## Architecture — key components

| Component | Role |
|-----------|------|
| `main.py` | ASGI entrypoint; serves the app at `/` and `/socx_sim/` |
| `cloud_mock_server.py` | FastAPI app: `_getRecommendation`, UI + JSON APIs |
| `permanent_responses.py` | Pinned, exact rule sets for specific networks |
| `response_template.py` | Global, editable template (dst = request network) |
| `cc_manager.py` | Configures Cyber Controllers over SSH; CC registry |
| `static/ui.html` | The web UI served at `/ui` |
| `Docker` + volume | One-command run; `socx-sim-data` persists state at `/app/data` |

## The user interface — `https://<host>:8080/ui`

A vertical-tab web app with a live status header (online state, version,
auto-detected endpoint + copy button).

**Tab 1 — Cyber Controller**
Enter the CC host + SSH creds (sim address auto-detected). One click:
sets `socx.*.cloud.hostname`, imports the TLS cert into ADE’s truststore,
restarts ADE. **Test connection** runs read-only preflight checks first, and
Configure **aborts before touching anything** if a check fails. Per-row
**Reset** restores a CC to its original state.

**Tab 2 — Recommendation**
Edit the JSON returned for non-pinned requests. `destinationIPs` always matches
the request; every other field is optional. **Preview** shows the exact response.

**Tab 3 — Recommendations**
Browse pinned + seeded rule sets in a table, **View JSON**, and
**Copy to Template** to reuse one as a starting point.

## CLI access to the stored files

Both state files live in the Docker volume **`socx-sim-data`**, mounted inside
the container at **`/app/data`**.

**Registered Cyber Controllers → `configured_ccs.json`**

```bash
# Read straight from the running container (pretty-printed)
docker exec socx-sim cat /app/data/configured_ccs.json | python3 -m json.tool
```

**All recommendations (editable template) → `response_template.json`**

```bash
docker exec socx-sim cat /app/data/response_template.json | python3 -m json.tool
```

> The **pinned** per-network recommendations are defined in code
> (`permanent_responses.py`), not in the data volume.

---

## CLI access — via the host volume

If the container isn’t running, read the files directly from the volume on the
host:

```bash
# Find where Docker stores the volume on disk
VOL=$(docker volume inspect socx-sim-data --format '{{ .Mountpoint }}')

# Registered CCs
sudo cat "$VOL/configured_ccs.json" | python3 -m json.tool

# All recommendations (template)
sudo cat "$VOL/response_template.json" | python3 -m json.tool
```

```bash
# Optional: copy a file out of the container to your current directory
docker cp socx-sim:/app/data/configured_ccs.json ./configured_ccs.json
```
